# Tagy — документация

## Структура проекта

Tagy ожидает следующую структуру директорий:

```
project/
├── config.yaml      # конфигурация сайта
├── content/         # страницы (Markdown / HTML)
├── layout/          # Jinja2-шаблоны
├── static/          # статические файлы (копируются в public/ как есть)
└── public/          # результат генерации (создаётся автоматически)
```

## config.yaml — конфигурация сайта

Файл `config.yaml` загружается целиком как объект `site`. Все поля из YAML становятся атрибутами `site`.

### Встроенные поля site

| Поле | Тип | Описание |
|------|-----|----------|
| `site.pages` | list | Список всех загруженных страниц. Заполняется автоматически из `content/` |
| `site.indexes` | dict | Описание индексов (тегов, категорий и т.д.) — см. раздел «Индексы» |

### Пользовательские поля site

Любое поле из `config.yaml` доступно как `site.<имя>`. Например:

```yaml
domain: imelnikov.ru
title: Мой сайт
author: Ivan
```

В шаблоне: `{{ site.domain }}`, `{{ site.title }}`, `{{ site.author }}`.

Несуществующие поля возвращают `None` (не вызывают ошибку).

## Страницы (content)

Файлы из `content/` загружаются как страницы. Поддерживаются форматы `.md` и `.html` — содержимое обрабатывается Markdown-парсером (mistune).

### Формат страницы

```markdown
title: Заголовок
layout: post.html
tags: [python, web]
date: 2024-01-15
---
Содержимое страницы в **Markdown**.
```

Всё до разделителя `---\n` парсится как YAML (frontmatter). Всё после — содержимое страницы.

### Встроенные поля page

Эти поля вычисляются автоматически при загрузке страницы:

| Поле | Тип | Описание |
|------|-----|----------|
| `page.content` | string | HTML-содержимое страницы (Markdown уже преобразован в HTML). Перед рендерингом обрабатывается как Jinja2-шаблон |
| `page.name` | string | Имя файла без расширения. Для `content/blog/post.md` → `post` |
| `page.path` | string | Путь от `content/` без расширения. Для `content/blog/post.md` → `blog/post`. Для `content/blog/index.md` → `blog` |

### Специальные поля page

Эти поля можно указать в frontmatter, и они влияют на поведение генератора:

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `page.layout` | string | `index.html` | Имя шаблона из `layout/`, используемого для рендеринга страницы |
| `page.url` | string | — | Если указан, страница записывается в `public/<url>` напрямую (вместо `public/<path>/index.html`) |
| `page.pagination` | object | — | Объект пагинации, создаётся автоматически функцией `paginate()`. Содержит `page_num` |

### Пользовательские поля page

Любое поле из frontmatter доступно как `page.<имя>`. Например:

```yaml
title: Мой пост
date: 2024-01-15
tags: [python, web]
author: Ivan
custom_field: значение
```

В шаблоне: `{{ page.title }}`, `{{ page.date }}`, `{{ page.custom_field }}`.

Несуществующие поля возвращают `None`.

## Индексы

Индексы группируют страницы по значениям указанного поля (теги, категории и т.д.). Настраиваются в `config.yaml`:

```yaml
indexes:
  tags:
    url: /tags
    layout: tag.html
  category:
    url: /category
    layout: category.html
```

Каждый ключ в `indexes` — имя поля страницы, по которому строится индекс. Если у страницы есть поле `tags: [python, web]`, то она попадёт в индекс `tags` под термины `python` и `web`. Поле должно быть списком.

### Поля индекса

| Поле | Тип | Описание |
|------|-----|----------|
| `url` | string | Базовый URL для страниц индекса. Страница термина `python` будет на `<url>/python` |
| `layout` | string | Шаблон для рендеринга страниц индекса |
| `terms` | dict | Заполняется автоматически. Словарь `{термин: [список страниц]}` |

### Шаблон индекса

В шаблоне индекса доступны переменные:

| Переменная | Тип | Описание |
|------------|-----|----------|
| `term` | string | Текущий термин (например, `python`) |
| `pages` | list | Список страниц с этим термином |
| `site` | object | Объект сайта |

## Шаблоны (Jinja2)

Шаблоны лежат в `layout/`. Используется стандартный Jinja2 с дополнительными фильтрами и функциями.

### Контекст шаблона

При рендеринге страницы в шаблон передаются:

| Переменная | Описание |
|------------|----------|
| `page` | Текущая страница со всеми полями |
| `site` | Объект сайта (конфиг + `pages` + `indexes`) |

### Фильтры

#### `where(param, value=True)`

Фильтрует список объектов по значению поля.

```jinja2
{# Все страницы, у которых есть поле "featured" #}
{{ site.pages | where("featured") }}

{# Страницы, чей path начинается с "blog" #}
{{ site.pages | where("path", "blog") }}

{# Страницы с определённым числовым значением #}
{{ site.pages | where("priority", 1) }}
```

Логика сравнения:
- `value=True` (по умолчанию) — проверяет, что поле существует
- `value` — строка → проверяет `startswith`
- `value` — число → проверяет точное совпадение

#### `breadcrumbs`

Разбивает путь на цепочку хлебных крошек.

```jinja2
{# "blog/2024/post" → ["blog", "blog/2024", "blog/2024/post"] #}
{{ page.path | breadcrumbs }}
```

#### `thumb(size=(100, 100))`

Создаёт миниатюру изображения и возвращает путь к ней. Использует Pillow.

```jinja2
<img src="{{ '/img/photo.jpg' | thumb }}">
<img src="{{ '/img/photo.jpg' | thumb((200, 200)) }}">
```

Миниатюра сохраняется рядом с оригиналом с суффиксом размера (например, `photo-100x100.jpg`).

### Тесты

#### `equalto`

Проверяет равенство двух значений.

```jinja2
{% if page.status is equalto "published" %}...{% endif %}
```

### Глобальные функции

#### `paginate(items, per_page=10)`

Разбивает список элементов на страницы. Автоматически создаёт дополнительные страницы.

```jinja2
{% set p = paginate(site.pages | where("path", "blog"), 5) %}

{% for item in p.items %}
  <a href="/{{ item.path }}">{{ item.title }}</a>
{% endfor %}

{% if p.has_prev %}
  <a href="/{{ p.base_path }}/{{ p.prev_num }}">← Назад</a>
{% endif %}
{% if p.has_next %}
  <a href="/{{ p.base_path }}/{{ p.next_num }}">Вперёд →</a>
{% endif %}
```

Возвращаемый объект пагинации:

| Поле | Тип | Описание |
|------|-----|----------|
| `items` | list | Элементы текущей страницы |
| `page_num` | int | Номер текущей страницы (начиная с 1) |
| `total` | int | Общее количество элементов |
| `per_page` | int | Элементов на странице |
| `total_pages` | int | Общее количество страниц |
| `has_prev` | bool | Есть ли предыдущая страница |
| `has_next` | bool | Есть ли следующая страница |
| `prev_num` | int/None | Номер предыдущей страницы |
| `next_num` | int/None | Номер следующей страницы |
| `base_path` | string | Базовый путь для ссылок пагинации |

URL дополнительных страниц: `/<base_path>/2`, `/<base_path>/3` и т.д.

## URL страниц

По умолчанию страница `content/blog/post.md` генерируется в `public/blog/post/index.html` (чистые URL).

Особый случай: `content/blog/index.md` генерируется в `public/blog/index.html` (без дублирования `/index/index.html`).

Если указано поле `url` в frontmatter — файл записывается по указанному пути напрямую: `url: blog/feed.xml` → `public/blog/feed.xml`.

## CLI

```bash
# Генерация сайта
tagy --build

# Сервер разработки с автоматической перегенерацией
tagy --serve
tagy --serve --port 8080
```

Сервер следит за изменениями в `content/`, `layout/` и `static/` и перегенерирует сайт автоматически.
